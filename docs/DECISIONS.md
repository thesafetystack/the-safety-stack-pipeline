# Decisions

Every implementation decision from D801 on, one row each. D0-D800 are in `docs/repo-history/decisions-D1-D800.md`,
unchanged; a `D<n>` citation resolves in this file or, for n up to 800, there. Commit ids cited in those older rows
refer to the pre-publication repository and do not resolve in this one.

- **Append-only.** A new decision is a new row with the next free number; a decided row is not edited. A later row
  amends or supersedes an earlier one and says so (`amends D<n>`, `supersedes D<n>`).
- **Row format.** `| D<n> (<short label>) | **<the decision, one sentence>** <details: what, where in the code,
  why> | <date, and how it was decided> |`. A row whose status says "default taken" records the implementer's
  default where the design or the maintainers left a choice open; it is in force until a later row overrides it.
- Code comments and docs cite rows as `D<n>`.

| D801 (s2-spans) | **`collect.semantic_scholar` sends the floor as a date filter on a query's first pass, and asks a tail or hole that crosses 1 January of a recent year as consecutive year spans, oldest first, each banked as its own `ok` coverage window `[s, e]`; a query's sequence stops at the first span that is not `ok`, and the next run resumes after the last `ok` span. Option `split_years` (default 4 in code: in 2026 the split points are 1 January 2023, 2024, 2025 and 2026); no cursor or token is persisted.** (1) **Cause**: D800 (1) and (4): a query with no coverage was sent no date filter when the plan floor was at or below the channel's `from_date` (`windowed` false), so its first pass paged the whole index (~118k papers for `group:llm-safety`, ~45 % of them before the 2015 floor and dropped locally), and a pass that hit the cap or a page still answered 429 after the D550 waits claimed nothing and restarted from page 1 on the next run. (2) **First pass filtered**: the special case is gone: every request carries `publicationDateOrYear=<from>:…`, the floor on a first pass, the watermark (less the D551 look-back) on a resumed one. Papers without a publication date, which the filter drops, are no longer seen on a first pass either (D272 accepted that loss for holes). This supersedes D800 (1)'s "a query with no coverage is sent no date filter" and D800 (4) for S2. (3) **Spans** (`year_spans`): split points are 1 January of each of the last `split_years` calendar years, used only strictly inside the range; the years before them are one span (sparse for most groups). A span other than the last sends the bounded `publicationDateOrYear=<s>:<e − 1 day>` (the existing hole request) and is written `[s, e]`; the tail's last span stays open above and written `[s, today]`; the D551 look-back applies to the tail's first span only. Calendar dates, not `date_windows(…, 365)`, so no leap-year drift; 1 January because S2 does not document where a year-only paper falls in a range that starts mid-year. Holes are split the same way, each hole's sequence stopping at its first span that is not `ok` (the rest stays a hole), as `collect.lw_graphql`'s `sweep_tag` and D645. Coarse on purpose: each span is at least one request, so a first pass from 2015 is at least 5 requests a query (60 queries, a full re-sweep: at least 300, ≈ 12.5 min at 2.5 s), while the weekly tail stays one span (one request for a query with under 1,000 papers in it; two spans in the week that crosses 1 January). One span's papers are held at a time, so the collector's peak memory is that of the largest span, not of the whole pass. (4) **Third backstop**: a bounded span that returns a paper dated after its last day beyond the one-day slack (`_FILTER_SLACK_DAYS`, the lower check's) proves S2 ignored the upper bound; the span claims nothing (`failed_permanent[query_invalid]` over `[s, s]`, `error` names the bound and the date; counted `upper_bound_ignored`), its sequence stops, and its papers are still observed. Permanent rather than transient: it is a provider contract change that a retry does not fix, so the build warns (`windows_failed_permanent.query_invalid`) and the query stays due. The lower-bound check (`filter_ignored`) now runs on every span: a complete span whose lower bound was ignored claims from the floor, as before. Any other span that is not complete writes `[s, s]` (on a first pass `[floor, floor]`, the key a failed first pass used before, so `attempts` accumulate as before). (5) **Counters**: new `spans`, `upper_bound_ignored`, `split_years`; `windowed` is dropped (every pass is filtered); `queries_complete` / `queries_truncated` / `queries_error` count spans. (6) **Digests**: the coverage key (`coverage_query`) does not change: the plan's 60 query digests computed before and after the change are identical, so nothing is re-swept; the default lives in code, so no plan line, line digest or plan digest moves (`ff4932034e2e136d…` stays); the code digest does. (7) **Live check** (local throwaway store, `group:llm-safety` from 2025-01-01, run `rssjpxcbvgvs5`, 2026-11-03): two spans, both `ok`, `[2025-01-01, 2026-01-01]` seen 1,035 and `[2026-01-01, 2026-11-03]` seen 1,391; 18 pages, 35 requests of which 17 were 429s waited out, 4.4 min; 17,129 papers fetched, 14,627 cut as publisher works; `filter_ignored` 0, `upper_bound_ignored` 0. Tests (`tests/test_collect_s2.py`): `test_year_spans_split_on_1_january_of_the_last_n_years`, `test_ignored_upper_bound_is_detected`, `test_s2_year_spans_bank_and_resume_after_a_failed_span` (a 503 past the ladder on the 2024 span: 2021-2022 and 2023 banked, 2024 `failed_transient` over `[2024-01-01, 2024-01-01]`, 2025 not asked; the next run asks `2023-12-02:2024-12-31`, 2025, `2026-01-01:`; a week later one open-ended request), `test_s2_ignored_upper_bound_claims_nothing`; updated: `test_page_budget_stops_the_run` (the first pass at the channel floor now sends the floor as the bound of its first span; its fixture papers moved into that span), `test_floor_moved_back_pulls_only_the_gap` (the hole in two year spans, on a fixed clock), `test_semantic_scholar_end_to_end` (pinned to `split_years: 0`: it checks the one-window properties on the real clock), and `tests/test_passes_collect.py`'s S2 line (`split_years: 0`: its fake S2 search answers a paper dated today whatever the date range, and its pass tests count one request a query). Docs: the module docstring ("Incrementality", "Year spans", options), `stack/collect/base.py` ("Date sub-windows"). | 2026-11-03, step 2 and year spans decided; span form and defaults chosen in implementation |
| D802 (s2-span-fixes) | **Follow-ups to D801 from its review: (1) a bounded span whose upper bound S2 broke is asked again open above from the same lower bound and, when that answer is complete, banks `[s, today]`; (2) `Collector.last_attempt` breaks a tie on `last_attempt_at` in favour of the row that is not `ok`; (3) the scheduled cycle WARNs on an S2 run's `failed_permanent` windows and broken upper bounds; (4) D801's statements on `max_records`, memory and the build warning corrected.** (1) **Cause**: D801 (4) wrote a span with a paper dated past its last day `failed_permanent[query_invalid]` and stopped the query's sequence there. One such record is enough (a date that moved between index and answer, or a year and a date that disagree), and the same request gets the same answer in every later run, so the later spans of the tail were never asked again, while `failed_permanent` kept the run `scope_complete` and no warning reached the cycle (see (3)). **Fix** (`sweep_span`): the span is asked again open above from the lower bound it was asked from (the D551 look-back on the tail's first span), counted `upper_bound_fallback` beside `upper_bound_ignored`; an open-ended request does not rely on the upper bound, so a complete answer banks `ok` `[s, today]` (from the floor when its lower bound was ignored), which covers the query's later spans, holes and tail for the run (they are not asked). A fallback that is not complete writes its own outcome over `[s, s]` (`partial`, `failed_*`), its `error` naming the broken bound, and the sequence stops. With no page of the run's `max_pages` budget left for the fallback the span is `failed_permanent[query_invalid]` as in D801 and the run is a budget stop (`scope_complete = false`, so the cycle's second S2 run asks the fallback). The bounded answer's papers are still observed. **Holes**: the same rule. Under D801 a hole span with a broken bound left the rest of the hole a hole, asked and failed again every run (the tail was not blocked); the fallback from the hole span covers the rest of the hole and the already covered tail, which is fetched again once: a cost accepted because holes come only from a floor moved back. (2) **Cause**: one run stamps every window it writes with its `now`, and `max` returned the first tied row of the view, with year spans an `ok` span, so D492's `capped_not_due` did not apply and a capped span was asked again within `relist_after_h` (12 h; in production by the cycle's `s2-collect-2`). **Fix**: on a tie a `failed_*` row ranks above a `partial`, a `partial` above an `ok`. Other collectors: `collect.blogs`, `collect.feeds`, `collect.manual` and `collect.cards` write one window per unit per run, so no tie; `collect.openalex`, `collect.arxiv_sweep`, `collect.forums` (a hole and the tail) and `collect.lw_graphql`, `collect.af_graphql` (date sub-windows) can write several rows of one query in a run and call `due` with `until` and `partial_due=False`, for which an `ok` pick never held a unit back; their one change is that a run that wrote a cap `partial` beside `ok` rows now holds the unit back within `relist_after_h` (`capped_not_due`), as D492 says, where the view's order decided before. (3) **Visibility**: D801 (4) said the build warns on the `failed_permanent` span; in production S2 runs as a standalone `stack run` (D554), and the build's `failed_permanent_note` (`stack/build.py`) sees only the runs of the build. `tools/scheduled_run.py` (`s2_collect_note`, `Cycle.s2_note`) now reads each standalone S2 run's record (`s2-collect` and `s2-collect-2`) from the store index and WARNs with `failed_permanent_note`'s text and the `upper_bound_ignored` / `upper_bound_fallback` counts; a record it cannot read is a WARN too. (4) **Corrections to D801**: `max_records` caps each request sequence, so each span, not the query: a first pass in year spans may fetch `split_years + 1` times it (D800's 250,000: up to 1.25 M on a first pass), more with a look-back or fallback re-ask; the option text that said "per-query result cap" is corrected. D801 (3)'s "peak memory is that of the largest span" is wrong: one request's `papers` are held at a time, but the observed rows (`Collector._rows`) accumulate over the whole run until `finish`; the module docstring says so now. Tests: `tests/test_collect_s2.py` `test_s2_ignored_upper_bound_falls_back_open_ended` (`fallback`, `no-page-left`; replaces `test_s2_ignored_upper_bound_claims_nothing`), `test_s2_one_late_record_does_not_block_the_tail` and `test_s2_late_record_in_a_hole_span_covers_the_rest` (the review's reproduction and its hole variant), `test_s2_capped_span_not_asked_again_within_relist_after` (`one-span`, `year-spans`); `tests/test_collect_base.py` `test_last_attempt_prefers_the_row_that_is_not_ok_on_a_tie`; `tests/test_passes_collect.py` `test_s2_default_year_spans_over_passes` (the default `split_years` on the passes harness: its search answers a paper dated today to every range, so the fallback; the harness's other S2 lines stay at `split_years: 0`); `tests/test_scheduled_run.py` `test_s2_collect_failed_permanent_and_broken_bounds_are_a_warn`, `test_s2_collect_note_reads_the_run_record`. Docs: the module docstring ("Year spans", `max_records`), `Collector.last_attempt`, `docs/DEPLOY-railway.md` (step 3, the WARN row). | 2026-11-03, from a review of D801 (9fea7ba); the hole rule chosen in implementation |
| D803 (release-format) | **The dataset release has a format with a semantic version, 1.0.0 first (`format_version` in `configs/releases/dataset/mapping.yaml`), separate from the dated `release_id`: `release.json` `format_version` replaces the date-valued `format`, the parquet key-value metadata carries `format_version` and `release_id` (`stack.format` is gone), the card's front matter `format_version`; each file's JSON Schema ships beside it (`release.schema.json`, `data/corpus.schema.json` (was `schema.json`), `config/configs.schema.json`, `config/overrides.schema.json`), each `$id` `urn:the-safety-stack:format:<major>.<minor>:<path>`; the schemas must equal the data repository's archive of the declared version (`data-repo/formats/<major>.<minor>/`, stripped of prose, compared structurally); the release checker `data-repo/tools/release-validator.py` ships byte-identical as `tools/release-validator.py` and `check_bundle` runs it over every row of every export, replacing the 200-row JSON Schema check and the checks it covers (doc ids, config and override ids, the manifest).** Details: (1) the row schema gives every node `x-arrow` (`struct`, `list` or the leaf's Arrow type); a closed list is an `enum`, an open list `x-open: true` with its known values in `x-values`, and an open list with `in_schema: false` (the providers' `doc_type`) has neither, its values only in VOCABULARY.md; the flag is set once per field in the mapping. Closed: `published_precision`, `field_sources[].origin`, `content.quality`, `release.abstract`, `release.text`, the metadata's `status`, `origin`, `provenance`, every payload `verdict`, `match_class`, `translation.method`. Open: `field_sources[].field`, `identity.members[].channel_class`, `content.role`, `screen.buckets`, `shallow_review_relevance.category`, `text_usability.issues`, affiliation `resolution` and `org_status`, both `doc_kind`; `identity.members[].key_kind`, `identity.keys[].kind` and `metadata.kind` stay open as they were (default taken: the decided lists do not name them). (2) The compatibility rules are the data repository's (`formats/README.md`): a major removes, renames, retypes, loosens nullability or changes a closed list or a meaning; a minor adds a field, file, open-list value or taxonomy key, or tightens nullability; a patch is prose. `tools/release_format.py` generates and strips the schemas, classifies a change on a flattened path table (path, JSON type, `x-arrow`, nullable, closed values, open flag and values, required, any other keyword = major), checks the declared version (equal to its archive, or a large enough bump over the highest lower one and a changelog entry), and writes `formats/<major>.<minor>/` into a data-repository checkout. (3) The models 1.1.0 → orgs 0.2.0 gap: the export ships every taxonomy version a shipped file's `meta.references` names, from the vendored files by tag and sha256, its `release.json` pin marked `referenced_by`, so `taxonomies/orgs-0.2.0.yaml` ships beside 0.2.2 (+1.3 MB) and every reference resolves within the release; FORMAT names it, `newest_taxonomy` and the organisation check skip such a file, and the checker refuses a release that lacks a referenced version (the alternative, narrowing the check, would leave models' maker ids unresolvable in a download). (4) The checker validates rows with a compiled predicate for the schema keywords the row schema uses (jsonschema for anything else and for the error paths; tested to agree), so every row costs ~0.2 ms: the whole checker took 28 s on the 41,435 rows of release 2026-11-02 converted to this format, 37 s (633 MB peak) on its internal variant. Run from the data repository it also compares a release with the archive and requires a shipped taxonomy file of a version the repository has to be that file byte for byte (whose schema check is the repository's CI) instead of re-running the taxonomy validator on it (~12 s per export). | 2026-11-03; the format's shape, names and lists decided by the maintainer on a reviewed proposal; (3), (4) and the unnamed lists default taken in the implementation |
