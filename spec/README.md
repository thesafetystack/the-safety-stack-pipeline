# spec/ — live machine-readable artifacts from the v3 spec

The v3 prose spec (`README.md`, `00-goals-and-desiderata.md` … `40-decisions.md`, `reviews/`) moved to
v3's `spec/`; the v4 design is `docs/DESIGN.md`. What stays here is still read:

- `schemas/config/*.schema.json` — validated by `tools/check_configs.py` (each `configs/*.yaml` against the schema of
  its name) and `tests/test_config.py`; `models.schema.json` is generated by `tools/gen_models_schema.py`.
- `schemas/payloads/screen_verdict.schema.json`, `doc_class.schema.json` — loaded by `workflows/annotate/screen/main.py`
  (the screen verdict and its doc_class question); `_core.schema.json` holds the one `$defs` entry they `$ref`
  (`grounding_idx`). `tools/check_configs.py` checks their `x-enum` tags against `configs/enums.yaml` and validates
  one example of `examples/payloads/` against each.
- `examples/payloads/` — one example per payload schema above (`_core.json`, `screen_verdict.json`, `doc_class.json`).
- `types/interfaces.py` — the `Anchorer` protocol (`stack/anchor.py`, `tests/test_anchor.py`, `tests/test_llm.py`)
  and the `tools/check_all.py` mypy leg; `tools/check_configs.py` checks its `RunStatus`, `Phase`, `LicenseClass`
  Literals against `configs/enums.yaml`.

v3's other payload schemas (`author_affiliation`, `claim`, `facet_observation`, `identity_observation`,
`proposal`, `receipt`, `result`, `support_check`, `tech_index_row`), all aggregate schemas (`schemas/aggregates/`),
the v3 `_core.schema.json` (the reserved payload core: `evidence_tier`, `independence`, `relation`, `stance`,
`date_asserted`, `confidence`), `schemas/config/workflows.schema.json` (v3's `workflows.yaml`, retired) and their
examples moved to v3's `spec/schemas/` and v3's `spec/examples/` (2026-10-14): only `tools/check_configs.py`
read them, and v4 types its payloads in code (`stack/schemas/payloads/registry.py`). The `configs/enums.yaml`
vocabularies only they named went with them (v3's `configs/enums.yaml`, the whole v3 file).
