The catalogues the pipeline reads. The released ones are relative symlinks into `data-repo/`, the subtree of the
data repository thesafetystack/the-safety-stack (below), pinned by tag and sha256 in `vendored.lock.yaml`; the drafts
and older catalogues that eval sets and non-production stages still read are regular files. The taxonomy's working
history and source corpus are not in this repository (root `README.md`, "What is not in this repository").

## The data repository subtree

`data-repo/` is the data repository (taxonomy releases, their JSON Schemas: the shared envelope
`taxonomies/schemas/catalogue-0.schema.json` and one per catalogue, which `stack/catalogue.py` reads; the validator),
added as a squashed git subtree. `git rev-parse HEAD:data-repo` equals the tree (`git rev-parse <commit>^{tree}`) of
the data-repository commit it holds. Edit taxonomies in the data repository, then update the subtree from the
repository root (a clean tree):

```bash
git subtree pull --prefix=data-repo https://github.com/thesafetystack/the-safety-stack.git main --squash
uv run --no-sync pytest tests/test_vendored_taxonomies.py -q     # a released file must not change
```

A new version then gets a symlink here (or, for the models, `configs/models.yaml` re-pointed) and an entry in
`vendored.lock.yaml`; keep a superseded path while a pin, an eval set, a stored run or a test names it. Changes made
under `data-repo/` in this repository (orgs 0.2.2 was written here first, D778) go back with `git subtree push
--prefix=data-repo <data repo> <branch>` or a pull request there.
